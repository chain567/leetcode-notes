## Idea
I used two pointer to manage the left and right of the arr. Since it is sorted, it is similar to the [16. 3Sum Closest](https://leetcode.com/problems/3sum-closest/description/?envType=problem-list-v2&envId=array) problem. 

**Time complexity: $\theta(n-k)$**

## Code
```python
class Solution(object):
    def findClosestElements(self, arr, k, x):
        """
        :type arr: List[int]
        :type k: int
        :type x: int
        :rtype: List[int]
        """
        n = len(arr)
        left, right = 0, n-1
        while right - left + 1 > k:
            if abs(arr[right]-x) >= abs(arr[left]-x):
                right -= 1
            else:
                left += 1
        return arr[left:left+k]
```

## Ideal Solution
Since it is a `sliding-window` problem, it is solved most efficiently in `sliding-window`. Think about the start of the window, and try to find the closest start.

1. We focus on the **start** of the sliding window. So the only possible choices of **start** is from `0` to `len(arr)-k`. 

2. Then, we are searching the closest window by comparing the value difference of `x` with `arr[mid]` and `arr[mid+k]`. This is because these two ends are the largest difference to `x`, and the window with ends that have closest value to `x` is the result.
3. Therefore, the problem is turned into a #binary-search problem. You are going to search the `arr[0:len(arr)-k]` array to find the closest `lo` and `hi`. After find the closest start, return the result.

**Time Complexity: $\theta (log(n-k))$**

```python
class Solution(object):
    def findClosestElements(self, arr, k, x):
        """
        :type arr: List[int]
        :type k: int
        :type x: int
        :rtype: List[int]
        """
        lo, hi = 0, len(arr)-k
        while lo<hi:
            mid = (lo + hi)//2
            if x-arr[mid]>arr[mid+k]-x:
                lo = mid + 1
            else:
                hi = mid
        return arr[lo:lo+k]
```
